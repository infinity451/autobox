# app/engine/ 引擎包说明

引擎（engine）是 AutoBox 的心脏，负责「规则是怎么被触发、怎么执行」的全部逻辑。
规则：**如果…就…**，比如「如果下载文件夹有新文件，就移动到 D:/视频」。

## 文件清单

| 文件 | 作用 | 一句话解释 |
|---|---|---|
| `__init__.py` | 包的身份证 | 告诉 Python「engine 是一个包」 |
| `rules.py` | 规则管理 | 对数据库里的规则做增删改查（CRUD），存的时候把字典转成 JSON 文本 |
| `matcher.py` | 条件匹配 | 判断「这个文件满不满足规则的条件」，比如「扩展名是不是 .mp4」 |
| `actions.py` | 动作执行 | 执行「移动/复制/重命名/通知」等动作，还负责把 `{{file.name}}` 模板变量替换成真实值 |
| `triggers.py` | 触发器 | 「盯」外部世界：用 watchdog 监控文件夹变化，用 APScheduler 定时到点触发 |
| `scheduler.py` | 引擎主控 | 把上面几块串成完整链路：接收事件 → 找匹配规则 → 执行动作 → 记日志；还处理防死循环 |

## 一条规则从创建到执行（完整旅程）

```
① 网页上填表 → ② rules.py 校验+存库 → ③ scheduler.py 加载规则并注册触发器
④ watchdog 发现新文件 → ⑤ scheduler 收到事件 → ⑥ matcher 判断条件满足
⑦ actions 执行动作（移动文件）→ ⑧ database 写日志 → ⑨ 网页日志区显示
```

## 重点设计：防死循环（看 scheduler.py）

「移动文件」这个动作本身会触发 watchdog 的「文件出现」事件，
如果不防护：移动文件 → 触发规则 → 又移动 → 无限循环。
解决方案：引擎把自己刚操作过的路径记下来（2 秒内），再收到同一路径的事件就忽略。

## 重点设计：路径规范化（Windows 坑，看 scheduler.py 的 _norm_path）

Windows 上同一个目录有两种写法：`D:/下载`（正斜杠）和 `D:\下载`（反斜杠）。
watchdog 返回反斜杠，用户可能填正斜杠，直接比较永远不相等。
所以比较前先把两边都统一成「正斜杠+小写」。

## 怎么测试

- `rules.py`、`matcher.py`、`actions.py` 可以单独用 `python -c "..."` 测试
- 完整链路测试：启动 `python main.py`，网页上建规则，往监控目录丢文件，看日志
