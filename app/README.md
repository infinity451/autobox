# app/ 后端代码说明

这是 AutoBox 的后端（负责干活的代码），用 Python 编写。
浏览器里的网页（前端）通过 HTTP 接口调用这里的代码。

## 文件清单

| 文件 | 作用 | 一句话解释 |
|---|---|---|
| `__init__.py` | 包的身份证 | 告诉 Python「app 是一个包」，本身不干活 |
| `database.py` | 数据层 | 管理 SQLite 数据库（建表、查数据、改数据、写日志），所有数据都存在 `data/autobox.db` |
| `models.py` | 规则数据模型 | 定义「一条规则长什么样」：触发器有哪几种、条件有哪些操作符、动作有哪些类型，还负责校验规则是否合法 |
| `api.py` | 接口层 | 网页和引擎之间的翻译官：把网页的请求（创建规则、删除规则…）转成 Python 调用 |
| `engine/` | 引擎包 | AutoBox 的心脏，处理「规则怎么被触发、怎么执行」（单独说明见 `engine/README.md`） |

## 数据流向（看这个图就懂了）

```
网页(static/) → api.py(接口) → engine/(引擎) → database.py(数据库)
     ↑                                              ↓
     └──────────────────────────────────────────────┘
网页点击"保存规则" → api 接收 → engine 加载 → 存进数据库
文件出现 → engine 的监控发现 → 匹配规则 → 执行动作 → 写日志 → 网页刷新看到
```

## 想改代码从哪看起？

- 想改「规则可以有什么触发器/动作」→ 看 `models.py`
- 想改「引擎怎么处理事件」→ 看 `engine/scheduler.py`
- 想改「接口返回什么数据」→ 看 `api.py`
