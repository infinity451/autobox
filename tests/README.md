# tests/ 单元测试说明

AutoBox 的单元测试（pytest），覆盖最核心、最容易出错的纯函数逻辑。

## 怎么运行

```bash
# 在项目根目录
.venv\Scripts\python -m pytest tests/ -v
```

当前 **36 个测试全部通过**（约 0.3 秒跑完）。

## 文件清单

| 文件 | 测什么 | 为什么重要 |
|---|---|---|
| `test_matcher.py` | 条件匹配（matcher.py） | 规则"满不满足条件"的判断逻辑，错一个规则就白触发 |
| `test_actions.py` | 模板变量替换（actions.py） | `{{file.name}}` 替换错，日志和文件名都会错 |
| `test_models.py` | 规则校验（models.py） | 覆盖优化清单 #4（目录校验）#5（定时规则禁文件动作）的新逻辑 |
| `test_rename.py` | 批量重命名（batch/rename.py） | 四种模式算法 + 冲突检测 + "绝不覆盖已有文件"的安全保证 |
| `test_paths.py` | 路径规范化（scheduler.py） | Windows 正斜杠/反斜杠的经典坑，之前真实踩过 |

## 为什么测这些

- 全部是**纯函数**（同样的输入 → 同样的输出），测起来稳定可靠
- 都是**改坏概率最高**的逻辑：条件判断、模板替换、校验、文件名算法、路径比较
- 以后改代码跑一遍测试，能立刻发现"改坏了什么"

## 加新测试的原则

- 修了一个 bug → 顺手加一个测试（防止它复发）
- 测试要能独立运行（用 pytest 的 tmp_path 造临时文件，不碰真实数据）
